**Error Logging and CHECK Constraints for COPY INTO and Snowpipe \- now Generally Available**  
Loads keep the good rows and send each bad row to a dedicated error table with the reason it failed. CHECK constraints are enforced at load, so dashboards and AI agents only see data that meets your business rules.

* Enable with one statement: ALTER TABLE ... SET ERROR\_LOGGING \= TRUE; no new COPY options  
* Fix rejected rows in SQL and reload just those rows, no full-file reprocessing  
* Replaces VALIDATE re-scans and custom quarantine code  
* Works on Snowflake-managed Apache Iceberg tables

[Docs](https://docs.snowflake.com/en/user-guide/data-load-error-tables) \| [CHECK constraints](https://docs.snowflake.com/en/sql-reference/constraints-overview#label-constraints-check) \| [Blog](https://www.snowflake.com/en/blog/engineering/snowflake-data-ingestion-error-logging-check-constraints/) \| [Release note](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-19-copy-snowpipe-error-logging-check-constraints-ga)

**Schema Detection and Evolution for Nested Data in COPY INTO and Snowpipe \- now Generally Available**  
Snowflake now detects and evolves fields inside nested objects and arrays, not just top-level columns. Pipelines keep running when sources add nested fields, with typed columns instead of hand-written DDL.

* Set INFER\_NESTED\_TYPES \= TRUE in INFER\_SCHEMA, COPY INTO and pipes (defaults to FALSE)  
* Parquet, JSON, Avro and ORC  
* Standard and Snowflake-managed Iceberg tables  
* New fields are added during the load, without stopping the stream

[Docs](https://docs.snowflake.com/en/user-guide/data-load-schema-evolution#label-schema-evolution-structured-types) \| [Blog](https://www.snowflake.com/en/blog/engineering/nested-schema-evolution-copy-snowpipe/) \| [Release note](https://docs.snowflake.com/en/release-notes/2026/other/2026-11-18-structured-type-inference)

**Code Bundles \- now Generally Available**  
Run existing Python, Java, Scala or Spark projects on Snowflake compute with one command, next to your data and without rewriting them into stored procedures. All bundle types, compute types and the SQL, REST, Python and CLI clients are GA.

* Java (JDK 11/17) and Scala 2.12 on standard warehouses  
* Compute pools for full Python runtimes, GPUs, scheduled notebooks and ML Jobs  
* Spark jobs via Snowpark Connect with async submit/poll/cancel for Airflow  
* Return values, run-from-stage for CI/CD, and a new Snowsight Code Bundles page

[Docs](https://docs.snowflake.com/en/developer-guide/code-bundles/code-bundles) \| [Blog](https://www.snowflake.com/en/developers/blog/code-bundles-python-spark-snowflake/) \| [Release note](https://docs.snowflake.com/release-notes/2026/other/2026-11-19-code-bundles-ga)
