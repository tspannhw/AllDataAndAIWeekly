### Snowflake Intelligence: Personal Work Agent

**Snowflake Intelligence** is now a personalized, context-aware AI agent that transforms how business users turn insights into action. It connects data, workflows, and external systems so users can move from questions to decisions to actions - all within a single experience grounded in enterprise data.

**Cortex Code** expands into a governed agent that works across your entire data stack - warehouse, transformation tools, and orchestration layers. Available as Desktop, CLI, and in Snowsight. **Cortex Agents** is the platform powering Snowflake Intelligence and enterprise AI agents. It orchestrates multi-step work across data, workflows, and external systems, with governance built in. Teams can build custom agents or use Snowflake Intelligence as a turnkey solution.

## **Cortex AI & Agents**

### Cortex AI Guardrails (GA - Apr 20)

**Cortex AI Guardrails** are now Generally Available. Part of Snowflake Horizon Catalog, they provide run-time protection against prompt injection and jailbreak attacks on Cortex Code.

**Release Notes:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-20-cortex-ai-guardrails-ga

**Documentation:** https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-ai-guardrails

### Cortex AI Function Studio (Limited Access)

**Cortex AI Function Studio** lets teams turn optimized AI logic (model, prompt, and evaluation) into reusable, governed SQL functions callable from queries and pipelines like any other Snowflake function.

**Documentation:** https://docs.snowflake.com/en/LIMITEDACCESS/snowflake-cortex/cortex-ai-function-studio

### Improved SQL Generation in Cortex Agents (Apr 13)

Cortex Agents that use **Cortex Analyst semantic views** as tools now generate SQL directly rather than delegating to the Cortex Analyst service. This results in improved accuracy and lower latency for analytical queries. No changes to agent configuration or semantic views required.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-13-cortex-agents-agentic-analyst

### Cortex Search Monitoring (Preview - Apr 14)

**Cortex Search request monitoring** is now in public preview. Enable request logging to collect detailed information about search requests including query patterns, response times, and request details. Logs are stored in the SNOWFLAKE.LOCAL.AI_OBSERVABILITY_EVENTS event table.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-14-cortex-search-monitoring

### Cortex Search Replication (GA - Apr 14)

**Cortex Search Service replication** is now GA. Replicate Cortex Search Services from a source account to one or more target accounts using replication or failover groups.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-14-cortex-search-replication-ga

### Auto-Generated Data Agents

**Auto-generated data agents** documentation for creating agents automatically from your data assets.

**Documentation:** https://docs.snowflake.com/en/collaboration/auto-generated-data-agents

### Cortex Agents Sharing

Documentation for **sharing Cortex Agents** across accounts and organizations.

**Documentation:** https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents-sharing

### AI Function Cost Management

Documentation for managing and monitoring **AI function credit consumption** across Cortex AI services.

**Documentation:** https://docs.snowflake.com/en/user-guide/snowflake-cortex/ai-func-cost-management

### Snowflake Documentation for AI Agents and LLMs (Apr 15)

Snowflake documentation is now **agent-friendly**. Hierarchical `llms.txt` at docs.snowflake.com/llms.txt follows a structured format so agents can fetch only the sections they need. Markdown rendering ensures clean consumption by LLMs. Reduces token usage and improves relevance.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-15-agent-friendly-docs

### Fine-Tuning Arctic Extract Models (GA - Apr 20)

**Fine-tuning arctic-extract models** is now GA. Adapt the model to your documents and domains for more consistent structured extraction, then run inference with AI_EXTRACT using your fine-tuned model. Now includes the `max_epochs` option.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-20-fine-tuning-arctic-extract-models-ga

## **Apache Iceberg Updates**

### Iceberg Tables with Snowflake Storage (Preview - Apr 14)

Create **Apache Iceberg tables that use Snowflake storage** - no external volumes needed. Snowflake stores and manages the Iceberg table files, with Fail-safe data protection just like standard Snowflake tables.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-14-iceberg-snowflake-storage

### Dynamic Iceberg Tables: Partition, File Size, Path Layout (GA - Apr 13)

**Dynamic Iceberg tables** now support PARTITION BY (identity, bucket, truncate, year, month, day, hour), TARGET_FILE_SIZE, and PATH_LAYOUT properties in General Availability.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-13-dynamic-iceberg-tables-partition-file-path

### Iceberg Description Propagation from External Catalogs (GA - Apr 20)

Snowflake **bidirectionally syncs table and column descriptions** between your external Iceberg REST catalog and catalog-linked database.

**Read more:** https://docs.snowflake.com/en/release-notes/2026/other/2026-04-06-iceberg-description-propagation

### Iceberg Tables with External Query Engines

Access Iceberg tables managed by Snowflake Horizon using **external query engines** (Spark, Trino, etc.).

**Documentation:** https://docs.snowflake.com/en/user-guide/tables-iceberg-access-using-external-query-engine-snowflake-horizon#considerations-for-accessing-iceberg-tables-with-an-external-query-engine

### Sync Data from Postgres to Snowflake with Iceberg and pg_lake

### Snowflake Shutdown SQL — Stop All Running Items

Use these SQL commands to suspend all active Snowflake resources and minimize credit consumption:

```sql
-- ============================================
-- STOP ALL SNOWFLAKE ITEMS
-- Run as ACCOUNTADMIN in Snowsight or SnowSQL
-- ============================================

-- 1. Suspend all warehouses
ALTER WAREHOUSE IF EXISTS GHOST_DETECT_WH SUSPEND;
ALTER WAREHOUSE IF EXISTS INGEST SUSPEND;

-- 2. Suspend Cortex Search services
ALTER CORTEX SEARCH SERVICE IF EXISTS GHOST_DETECTION.APP.SPIRIT_BOX_SEARCH SET TARGET_LAG = 'DOWNSTREAM';

-- 3. Suspend all tasks
ALTER TASK IF EXISTS GHOST_DETECTION.APP.REFRESH_GHOST_STATS SUSPEND;

-- 4. Suspend dynamic tables (already suspended, but verify)
-- ALTER DYNAMIC TABLE <db>.<schema>.<table> SUSPEND;

-- 5. Verify nothing is running
SELECT 'Warehouses' AS type, NAME, STATE 
  FROM SNOWFLAKE.ACCOUNT_USAGE.WAREHOUSES 
  WHERE DELETED IS NULL AND STATE = 'STARTED';

SHOW CORTEX SEARCH SERVICES IN GHOST_DETECTION.APP;

SELECT 'Tasks' AS type, NAME, STATE 
  FROM GHOST_DETECTION.INFORMATION_SCHEMA.TASK_HISTORY 
  WHERE STATE = 'STARTED'
  LIMIT 10;
```

Also available via shell: `./manage.sh snowflake-stop`
